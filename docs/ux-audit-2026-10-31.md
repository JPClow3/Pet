# UI/UX audit — 31 Oct 2026

Scope: every route in the app, the screens and components behind them, against
`design.md` (the current spec) and general usability and WCAG 2.2 AA checks.

Method: read the code for the shell, the UI primitives, the tokens and every
page, then used the app in a browser from a fresh install (Welcome → onboarding
→ Hoje → Meu pet → Agenda → Saúde → record form → Carteirinha → Descobrir →
Comunidade → Produtos → Notificações → Ajustes). I tested at 375 px (phone),
390 px tall captures, 1440 px (desktop), and in dark mode.

Severity scale:

- **P0**: broken, unsafe, or misleading in a way that can cause harm. Fix now.
- **P1**: real friction or a trust problem on a core flow. Fix before the next
  release.
- **P2**: inconsistency or polish that wears down quality over time.
- **P3**: nice to have.

---

## Summary

The foundation is strong. The tokens are well chosen and contrast is solid in
both themes (body text 4.6–7.2:1, buttons 5.8–6.3:1). Focus rings, the skip
link, the BottomSheet focus management, `aria-current` on navigation, draft
recovery and the reduced-motion handling are better than most production apps.
The welcome screen and onboarding are calm and quick.

The problems are mostly above the component level:

1. **One layout bug makes Descobrir unreadable on phones** (P0-1).
2. **Seeded demo data shows up as real, verified, callable information in
   emergency contexts** (P0-2, P0-3).
3. **Screens keep accumulating content.** Meu pet, Hoje, Carteirinha and
   Ajustes each stack 8–12 cards with repeated empty states, repeated CTAs and
   explanatory paragraphs. That cuts against the spec's "Today, not dashboard"
   and "one dominant accent" rules.
4. **The app reassures when it should not.** "Tudo organizado" and "Tudo em
   dia" appear when nothing has been recorded. That breaks "Truth over theatre".
5. **Navigation is not quite coherent.** Care tabs have no Perfil tab, the
   Agenda tab silently changes from one pet to all pets, page titles never
   change, and the onboarding back arrow leaves the wizard.

## P0 — fix now

### P0-1. Descobrir header collapses to ~15 px wide on phones

`src/app/(app)/explore/page.tsx:247-248`

At 375 px the eyebrow, H1 and description wrap one or two letters per line, so
the page is thousands of pixels tall before the first place appears. Measured:
the `h1` is **15 px wide** inside a 343 px row.

Cause: the title column is `min-w-0 flex-1` inside a `flex flex-wrap` row.
`flex-1` sets `flex-basis: 0`, so the row never wraps, and the button group
("Cadastrar local" plus the Lista/Mapa toggle) takes all the width.

Fix: give the title column a real basis, for example
`className="min-w-0 flex-1 basis-[18rem]"`, or stack the row below `sm`
(`flex-col sm:flex-row`). Then search for the same `flex-wrap` + `flex-1 min-w-0`
pattern elsewhere. It was the only page that broke in my pass, but the pattern
is easy to repeat.

### P0-2. Emergency guide offers a "Ligar agora" button for a fictional clinic

`src/components/first-aid-guide.tsx:115,176` · `src/lib/domain/seed.ts:91-108`

The first-aid screen ("Socorros & Comunidade") shows **Clínica Bicho Bem** with
**"Ligar agora ((11) 3062-0100)"** and a WhatsApp button. It is seed data, and
the only marking is a small "(exemplo)" label. A person whose pet is poisoned
is the least likely to read that label, and the number has a real São Paulo
format, so it may belong to someone else.

Fix: never render call or WhatsApp actions for `seeded` places, anywhere. In
the first-aid guide, if the user has not saved their own 24h clinic, show
"Salve sua clínica 24h de confiança" and a link to add one. Make
`(11) 0000-0000`-style numbers impossible in seed data.

### P0-3. Seeded places are marked `verified: true` and `openNow: true`

`src/lib/domain/seed.ts` (every seeded place)

Fictional places show "Emergência 24h" and verified styling, and Hoje lists them
under Descobrir with Ligar/WhatsApp buttons. The spec says:
"Offline shows saved/seeded places with freshness and disables fresh
route/open-status claims" and "do not present seeded activity as live".

Fix: seeded places should be `verified: false` and `openNow: undefined`, with
no contact actions (see P0-2). Use one consistent "Exemplo" treatment on the
card itself.

## P1 — fix before next release

### Navigation and orientation

**P1-1. Every in-app route has the same browser title.**
All `(app)` pages are `"use client"` with no metadata, so every tab, history
entry and screen-reader page announcement reads
"Zelupi — cuidados e história do seu pet". This fails WCAG 2.4.2 (Page Titled).
Fix: add a small server `layout.tsx` or `page.tsx` wrapper per route that exports
`metadata`, or set `document.title` from `PageHeader`. Only `account`, `p/[code]`,
`roadmap`, `sitter` and `~offline` set titles today.

**P1-2. Care tabs leave out the profile, and Agenda changes scope without
saying so.**
`src/components/care-tabs.tsx:25-31`
"Meu pet" opens the pet profile, but the tab bar shows only
Agenda / Histórico / Diário, so on the landing page no tab is selected and you
cannot get back to the profile from the tabs. "Agenda" goes to `/reminders`,
which is all pets ("Todos os pets"). Histórico and Diário are scoped to one pet.
Fix: tabs should be **Perfil · Agenda · Histórico · Diário**, all scoped to the
active pet. Keep "Todos os pets" only where the spec allows it (Hoje and an
explicit Agenda filter).

**P1-3. The onboarding header arrow leaves the wizard.**
`src/app/onboarding/page.tsx:320-325`
On steps 2–4 the top-left ← links to `/welcome`, while the footer "Voltar" goes
back one step. These are two backs with different meanings, and the most
prominent one throws the user out. Fix: make the header arrow go to the
previous step (and go to `/welcome` only from step 1).

**P1-4. Two back patterns inside the tabbed care area.**
Saúde shows the CUIDADOS eyebrow, the pet switcher and tabs, *then* a ‹ back
button and a second title ("Saúde" while the selected tab says "Histórico").
Pick one: inside the tabbed area, drop the back chevron and use the tab name as
the H1.

**P1-5. The nav label and the page title disagree.** The bottom nav says
"Ajustes", the page H1 says "Perfil", and the spec calls it "Perfil". Use one
name everywhere.

### Trust and truthfulness

**P1-6. False "all good" states.**
`src/app/(app)/page.tsx:237,352` · `src/app/(app)/reminders/page.tsx:344` ·
`src/lib/domain/health.ts:148`
With no records at all, Hoje shows a green success card, "Tudo organizado por
hoje". After one vaccine with no next date, Saúde and Meu pet say
"Tudo em dia por aqui" with an "Em dia" chip. The app doesn't know that.
Fix: three distinct states. **No data**: neutral, "Ainda sem cuidados
registrados" plus one CTA. **Has data, nothing due**: neutral or soft,
"Nada pendente até {next date}". **Due or overdue**: warning or danger. Keep the
success color for confirmed completions.

**P1-7. A "near you" notification appears before the user gives a location.**
`src/lib/domain/notifications.ts:143` · `src/lib/store/app-store.ts:276-282`
The first notification a new user gets is "3 lugares pet-friendly perto de
você", built from seed data. The city silently defaults to São Paulo
(`PILOT_CITY`) even though onboarding never asks for it, and the "Perto de
você" category is on by default. Fix: don't create `local` notifications until
the user has set a city or allowed location, and keep the first unread badge
for something about their own pet.

**P1-8. Seeded community posts show fake recency on Hoje.**
"Ana Cláudia · há 5 h · Veterinário de madrugada…" (a vomiting dog) appears on
Hoje. It is labeled "Exemplo local", but the relative time and the reaction
counts present it as live activity, against the spec's §7.9 last bullet. Fix:
drop timestamps and counts on seeded posts, and leave community content off Hoje
until it's real.

**P1-9. Products claim personalization the app can't do.**
"Ração Sênior Articulações… cães acima de 7 anos" is recommended for a dog with
no birth date. Pet food is "Disponível em Padaria Pão & Patas". Fix: filter by
known attributes only, or say "Exemplos — não personalizados ainda". Show the
demo disclaimer once at the top instead of repeating it on all 8 cards.

**P1-10. Implementation names leak into the UI.**
`src/components/pet-collaborators-panel.tsx:154,232,246`
"conecte uma conta **Neon**", "E-mail da conta **Neon**". Also
"OpenStreetMap", "PNG", ".ics" and "cache do app". Users have a *Zelupi*
account. Fix: replace "Neon" with "conta Zelupi", and replace file formats with
outcomes ("Adicionar à agenda do celular", "Baixar imagem").

**P1-11. Collaboration says "tempo real" in local-only mode.**
"Sincronização em tempo real de remédios" is shown while the user is local-only
("Conta local"). Say what happens now and what an account unlocks.

### Flow friction

**P1-12. The record type is chosen twice.**
`/record/new` asks "O que aconteceu?" with 8 tiles, then the form opens with the
same 8 tiles again. Fix: on the form, collapse the picker into a single
"Vacina · trocar" control.

**P1-13. Reminder opt-in is off by default for vaccines.**
In the record form, "Quero um aviso antes da próxima data" is unchecked, yet the
product's core promise is "Saiba qual é o próximo cuidado". For vaccine,
vermífugo and antiparasitário, pre-check it and suggest the usual interval
(the form already supports `recurrenceMonths`).

**P1-14. Lost mode is buried.**
On Carteirinha, "Ativar modo perdido" is below the account-gated link panel and
the whole share studio, roughly 1,300 px down on a phone. The spec (§6.5) treats
it as an urgent path. Fix: put lost mode first on the card page, or give it its
own screen reachable from Meu pet's header (the button there already exists).

**P1-15. The card page opens with a blocker.**
The first card is "Link público gerenciado → Entre e confirme seu e-mail".
Lead with the preview and the local PNG, which work without an account, and put
the account upsell after them. The preview reads "Contato não informado" but
offers no inline "Adicionar contato". The spec asks for "Adicione um contato
para deixar a carteirinha útil".

**P1-16. Destructive actions use `window.confirm`.**
`pets/[petId]/edit/page.tsx:139` · `profile/page.tsx:315` · `diary/page.tsx:306`
· `health/[recordId]/page.tsx:111` · `community/[postId]/page.tsx:199` ·
`medication-course-panel.tsx:370`
Native dialogs are unstyled, can't list consequences, and are blocked in some
installed-PWA contexts. The spec says "Pet deletion lists the affected local
records before confirmation" and "dismissal offers Undo". Fix: use a
`ConfirmSheet` on top of `BottomSheet` that lists the counts ("12 registros, 3
documentos, 5 momentos"), and offer an Undo toast for single-item deletes.

**P1-17. The danger zone isn't separated.**
In Ajustes, "Apagar dados locais" sits in the same row as "Baixar backup" and
"Restaurar backup". The spec (§7.12, item 9) puts it in a separate danger zone
at the bottom.

**P1-18. The theme ignores the OS setting.**
`src/app/layout.tsx:24`
The bootstrap script defaults to light and has no "system" option, so dark-mode
phones get a bright screen on first launch. Fix: Claro / Escuro / Automático,
with Automático as the default, using `prefers-color-scheme`. Also put the
setting under Ajustes → Aparência, since the spec lists appearance there.

## P2 — consistency and polish

### Information density

**P2-1. Meu pet is a 12-card scroll.** In order: hero with 5 pill actions,
completion nudge, agenda status, weight (empty), last records (empty), diary
(empty), documents, Multi-Tutor, Modo Cuidador, and a FAB on top. With a new pet,
three large empty states stack. Fix: collapse empty modules into one "Comece
por aqui" checklist, and move Multi-Tutor and Modo Cuidador into a single
"Compartilhar cuidados" row that opens a sheet.

**P2-2. Hoje repeats itself.** "Registrar cuidado" appears twice, "Carteirinha"
twice, and three links go to the same agenda or history ("Abrir tudo", "Ver
próximos cuidados", "Ver histórico e próximos cuidados"). The empty state is
said three times. The "Emergência 24h" fact appears three times on one place
card (badge, subtitle and chip).

**P2-3. Agenda shows the same counts twice.** The Atrasados / Hoje / Próximos
tiles and the filter chips below them carry the same information. Make the
tiles the filters. Also, "Criar lembrete" and "Registrar cuidado" are two
equal-weight primary buttons, and the difference isn't explained.

**P2-4. Saúde puts three tool buttons above the list** (Exportar histórico,
Exportar calendário (.ics), Modo Consulta). Move them into a "⋯" menu or below
the timeline. The records are the content.

**P2-5. Ajustes exposes internal analytics.**
`src/app/(app)/profile/page.tsx:335`
"Como o app está sendo usado" lists raw events, and in dev they already show
duplicates ("Onboarding iniciado" ×2, "Produto visualizado" ×2). Move this
behind a debug flag or into "Privacidade → Ver meus dados".

**P2-6. Ajustes has a duplicate consent control and a label bug.**
"Ofertas de parceiros" (notifications) and "Aceito receber ofertas de
parceiros" (privacy) are two controls for the same choice. Also
`profile/page.tsx:197` renders "Conteúdo identificado como comercial (conteúdo
identificado como comercial)" because the base description already contains the
suffix.

**P2-7. Ajustes order doesn't follow the spec.** The spec's order is tutor and
pets, notifications, location, privacy, storage, export, appearance, help, then
the danger zone. Today the account upsell comes first and storage internals
take a lot of space ("Pedir armazenamento persistente", quotas, cache).

### Visual system

**P2-8. Too many accent washes on one screen.** Hoje uses a cobalt hero, a mint
agenda card, a coral diary card and a cobalt Descobrir card. The spec allows
"no more than one non-semantic accent family in the main content viewport".
Keep the hero tinted and make the rest `paper` with hairlines.

**P2-9. Uppercase eyebrows on almost every group.** PRÓXIMO PASSO, CONTEXTO,
AGENDA DE CUIDADOS, DEPOIS DO CUIDADO, ESTÚDIO DA CARTEIRINHA, FORMATO, PALETA…
The spec says to limit them to short section labels, "never the current
poster-like treatment on every group". Keep at most one per screen.

**P2-10. H1s change typeface from screen to screen.** Hoje, Perfil do pet,
Agenda and Descobrir use Fraunces. Perfil, Novo registro, Saúde and Carteirinha
use Manrope. The spec says to "choose one family by surface". Define two
`PageHeader` variants (editorial and operational) and use them everywhere.

**P2-11. Type and radius scales have drifted.** There are 30+ arbitrary
`text-[x.xxrem]` sizes in use (0.65, 0.68, 0.7, 0.72, 0.75, 0.76, 0.78, 0.8,
0.82, 0.85, 0.86, 0.88, 0.9, 0.92, 0.95, 0.98…) against a spec with 7 roles,
and 12 radius values against 4 specified (14/18/24/28 plus pill). Add
`text-label`, `text-caption` and similar tokens in `@theme`, then replace the
arbitrary sizes. `Card` uses 20 px, but the spec says 18 px.

**P2-12. Text below the caption minimum.** Sizes 0.65–0.7rem (10.4–11.2 px)
are used about 30 times, including the bottom-nav labels (0.7rem) and the
notification badge. The spec's caption minimum is 12 px.

**P2-13. Touch targets below spec.** `FilterChip` is `min-h-9` (36 px) and there
are 24 more `min-h-9` / `h-8` controls. The spec says 44 px is the absolute
minimum. Raise them to `min-h-11`, or add an invisible hit-area pseudo-element.

**P2-14. The FAB covers content.** On Meu pet, "+ Adicionar" sits on top of the
Modo Cuidador buttons at the end of the scroll. Add bottom padding equal to the
FAB height plus the nav height on pages that show it.

**P2-15. Vermífugo and Medicamento share the same pill icon** in the record type
grid. Give each a distinct icon.

**P2-16. Placeholders look like values.** "Sem raça definida", "Vacina", "Luna"
and "12,4" are placeholders at 3.1:1 contrast. "Sem raça definida" and "Vacina"
look like pre-filled answers, and the record actually saves "Vacina" when the
field is left empty. Either prefill a real value or use "Ex.: Vacina V10".

**P2-17. Numbers aren't formatted for pt-BR.** Distances render as "1.6 km" and
"3.5 km" (`place-card.tsx:142`, `place-map.tsx:113,194`,
`explore/[placeId]/page.tsx:245`, `product-card.tsx:85`). Use
`Intl.NumberFormat("pt-BR", { maximumFractionDigits: 1 })`. The weight chart
already does this by hand.

**P2-18. English and mixed labels.** "Multi-Tutor & Família", "Modo Cuidador /
Pet Sitter", "Socorros & Comunidade", "Story", "feed". Choose Portuguese
("Cuidadores e família", "Modo cuidador").

**P2-19. The primary CTA on Welcome uses an external-link icon.**
"Começar com meu pet ↗" uses `ArrowUpRight`, which suggests it leaves the app.
Use `ArrowRight`, which onboarding already uses.

### Information architecture

**P2-20. First aid is filed under Comunidade.** The tab "Socorros &
Comunidade" puts emergency protocols next to a social demo. First aid is a
care tool, and the spec keeps social content away from the trusted care
surface. Move it to Hoje (an "Emergência" quick action) and to Meu pet, and keep
Comunidade social only.

**P2-21. The first-aid page is a wall of text.** All 25 entries render fully
expanded. That means 19 substances with 3 warning signs and a "Conduta" each,
plus 6 protocols. In an emergency, people search or tap a symptom. Collapse the
entries into a list, open one at a time, keep the quick-search chips at the top,
and put the user's own 24h clinic in a sticky bar.

**P2-22. The pet switcher appears with one pet.** "Thor ▾" opens a chooser with
one item, and the Agenda shows "1 Todos os pets · 1 pet". Show the switcher only
when there are two or more pets, and show "Adicionar pet" inside the sheet.

**P2-23. Completion nudge.** `pets/page.tsx:266` says "Faltam 6 detalhes… foto,
data de nascimento, raça." It names 3 of the 6, and the spec specifically avoids
count-based gamification. Name the single most useful missing field, for example
"Adicione um contato para deixar a carteirinha útil".

## P3 — nice to have

- The step chip "Só o necessário agora" also appears on onboarding step 3,
  where every field is optional. Use "Opcional" there.
- The Welcome screen has no pet photo (spec §7.1). The illustrated card is fine,
  but one warm photo would carry the emotion the copy is aiming for.
- The Sonner close button overlaps the toast's top-left corner. Use
  `closeButton={false}` or position it inside.
- On desktop, Hoje's left column ends early while the right column runs long,
  leaving empty space. Consider moving Diário and Ações rápidas to the left
  column.
- `Photo` has no `width` and `height` or aspect ratio, so layout can shift when
  user photos load (the spec says photos "never shift layout").
- In dev, analytics events fire twice (possibly StrictMode). Confirm in a
  production build before trusting the numbers.

## What's working (keep it)

- The tokens and both themes: contrast passes AA for text and controls in light
  and dark. Dark mode's on-color overrides (`.dark .bg-teal-ink.text-white`) are
  handled carefully.
- Accessibility basics: the skip link, 3 px focus rings, `aria-current` on
  navigation, `aria-pressed` on toggles, `Field` wiring `aria-describedby` and
  `aria-invalid`, and the BottomSheet's focus trap, restore and announcement.
- Onboarding: 4 short steps, only the name is required, drafts survive reloads,
  and skipping the first care record doesn't create a broken record.
- Honest copy where it exists: "Status da agenda, não avaliação clínica", the
  push-notification caveats, and the clinical disclaimers on Saúde and Produtos.
- Reduced-motion handling and no decorative motion on operational screens.

## Suggested order of work

1. **Same day:** P0-1 (one class), then P0-2 and P0-3 (seed data and
   contact-action guards).
2. **Trust pass:** P1-6, P1-7, P1-8, P1-9, P1-10, P1-11, plus pt-BR number
   formatting (P2-17).
3. **Navigation pass:** P1-1, P1-2, P1-3, P1-4, P1-5, P2-20, P2-22.
4. **Density pass:** P1-12 through P1-15, then P2-1 through P2-7.
5. **System pass:** type and radius tokens (P2-11), touch targets (P2-13),
   eyebrows and accents (P2-8 through P2-10), and `ConfirmSheet` (P1-16).
